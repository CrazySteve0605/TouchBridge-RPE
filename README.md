# 触控板制谱器 · TouchBridge → RPE

> 用 Mac 触控板采集多根手指的位置 / 轨迹 / 手势，实时生成 **Phigros / RPE** 谱面，一键导出 `.pez`，可直接游玩，也能丢进 PhiEdit / Phira 继续编辑。

---

## ⚠️ 适配警告（重点！请先读）

- **仅支持 macOS。** 触控板采集依赖苹果私有框架，Windows / Linux 完全用不了。
- **本工具属于个人本机调试作品，不是工业级成品。** 它读取触控板用的是苹果未公开（private）的 `MultitouchSupport` 框架。
- **触控板采集兼容性可能不适配所有机型 / 系统版本。** 绝大多数现代 MacBook 可用，但以下情况可能出问题，且不保证能修：
  - 很老（或很新）的 macOS 版本导致私有 API 符号变动；
  - 非苹果原厂触控板（外接第三方触控板、iPad 当触控板等）；
  - 不同机型的触控板坐标系 / 采样率差异导致的手感偏差（可用网页里的「采样补偿 / 自动校准」缓解）。
- **不提供任何运行保证。** 请把它当作一个「思路 + 可用雏形」来用和改，而不是开箱即用的商业软件。

如果你在某台 Mac 上跑不起来、或采集明显不准，欢迎到 [Issues](../../issues) 反馈机型 + 系统版本 + 现象，**但我们无法承诺一定修好**——这正是下面「欢迎一起来完善」的原因。

## 这是什么 / 它能干嘛

传统音游自制谱要么手摆、要么用 MIDI 键盘。这个工具换了个思路：

**把你笔记本电脑的触控板当成「多点触控打谱台」**——你用几根手指在触控板上做出 Tap / 长按 / 滑动 / 快扫 等动作，程序把每根手指的**坐标、区域、移动轨迹、手势类型**实时转成 OSC 消息，再由后端还原成音符，最后按 RPE 规范打包成 `.pez`。

- 导出后能**直接在 Phigros / Phira 里游玩**；
- 也能用 **PhiEdit（RPE 桌面版）/ Phira** 打开继续精修；
- 全部流程在你**自己这台 Mac 上本地完成**，不上传任何音频 / 数据。

### 支持的手势 → 音符类型

| 触控板动作 | 生成的音符 | RPE type |
|-----------|-----------|----------|
| 短按（落指即起，几乎没移动） | Tap（蓝键） | 1 |
| 按住不动 | Hold（长条） | 2 |
| 快速横扫 / 甩动 | Flick（红键，带方向） | 3 |
| 缓慢拖移 | Drag（黄键 + 轨迹） | 4 |

> Flick / Drag 的方向、轨迹都由程序根据手指运动自动判断，不需要你在 App 里选。

## 工作原理（三件套）

```
 你的手指
   │  在触控板上做动作
   ▼
┌──────────────┐   OSC (UDP, 127.0.0.1:9000)   ┌────────────────────┐   内部还原   ┌──────────────┐
│ TouchBridge  │ ───────────────────────────▶  │ 后端 (Flask+SocketIO)│ ──────────▶ │  RPE / .pez  │
│ (采集器 .app) │    /down /move /hold /drag     │ 手势分类 + 量化 + 导出 │            │  导出文件     │
└──────────────┘    /tap /up /count            └────────────────────┘             └──────────────┘
                                                                   │
                                                      网页前端 (浏览器)
                                                      实时预览 + 设置 + 录制 + 导出
```

- **TouchBridge（采集器）**：Swift 写的轻量 macOS  app，读取触控板原始多点触控数据，封装成 OSC 发给本机后端。
- **后端**：纯 Python（Flask + SocketIO），监听 OSC、把手势分类成音符、做节拍量化与吸附、导出 RPE/PEZ。音频由浏览器播放，后端只接收浏览器上报的播放时间当节拍时钟。
- **前端**：一个网页，负责音频播放、可视化预览、参数设置、录制控制、导出。

## 快速开始

### 1. 拿代码

```bash
git clone <本仓库地址>
cd touchbridge-rpe
```

### 2. 编译触控板采集器（重要，每台 Mac 都要自己编一次）

```bash
bash TouchBridge/build.sh
```

- 首次会让你装 Command Line Tools（弹窗点安装，或自己跑 `xcode-select --install`）。
- 脚本会 `swiftc` 编译 `main.swift` 并打包成 `TouchBridge/TouchBridge.app`，还会做本地自签名。
- **为什么必须自己编？** 见下方「关于『别人能不能跑』」一节。

**首次打开若 macOS 提示「无法验证开发者」被拦截，任选其一：**

```bash
# 方式 A：右键点击 TouchBridge.app → 打开（仅需一次）
# 方式 B：终端解除隔离
xattr -cr "TouchBridge/TouchBridge.app"
```

无界面自检（验证 OSC 能否正常发出，不需要打开 GUI）：

```bash
TouchBridge/TouchBridge.app/Contents/MacOS/TouchBridge --osctest
# 应输出：sent: 7
```

### 3. 启动后端 + 网页

最省事（macOS 双击即可）：

> 双击仓库根目录的 **`run.command`**

它会自动建 Python 虚拟环境、装依赖、杀掉旧实例、后台启动服务并打开浏览器。

手动也行：

```bash
cd backend
python3 -m venv venv
source venv/bin/activate
pip install -r ../requirements.txt
python3 app.py
# 浏览器打开 http://127.0.0.1:8765
```

### 4. 开始制谱

1. 网页里「上传音频」（你的歌），点播放确认有声音；
2. 打开 **TouchBridge.app**，确认状态灯是「正在发送 → 127.0.0.1:9000」；
3. 网页点「开始录制」，跟着音乐在触控板上打板；
4. 打完点「停止录制」；
5. 填好曲名 / 作曲者 / 谱面设计，点「导出」→ 得到一个 **`.pez`**；
6. 把 `.pez` 丢进 Phigros / Phira 游玩，或丢进 PhiEdit 继续改。

> 如果觉得音符整体偏早 / 偏晚，先录一段，再点网页上的「自动校准」，会自动估算采样补偿。

## 关于「别人的 Mac 能不能跑」——这是已知最大顾虑，也是我特意这样设计的原因

**结论：发的是源码 + 编译脚本，不是预编译的 .app，所以任何人都能在自己 Mac 上跑。**

具体原因：

1. **读取触控板用的是 `MultitouchSupport.framework`**，这是苹果系统自带的私有框架，**每一台 Mac 都有**，而且 `MTDeviceCreateList` / `MTRegisterContactFrameCallback` / `MTDeviceStart` 这几个符号多年来一直稳定。所以它不依赖我这台电脑的任何环境。
2. **用 `swiftc` 源码编译，编出来自动适配你自己的芯片**：在 Apple 芯片 Mac 上编出 arm64，在 Intel Mac 上编出 x86_64——不会有「架构不对跑不起来」的问题。
3. **刻意不发预编译 `.app`**：预编译包是某一台机器的架构 + 我的签名，换台 Mac 几乎必然被 Gatekeeper 拦、或架构不匹配。源码方案从根本上避开这两点。
4. 源码里**没有任何写死我电脑路径**的东西（只有系统框架路径），所以不存在「按我环境配的」问题。

**仍然可能的坑（诚实说明）：**

- 私有 API 在极老 / 极新的系统上可能变动 → 采集器编不过或读不到。
- 非原厂触控板（外接第三方、iPad 当板）可能读不到或多点异常。
- 不同机型触控板手感 / 坐标范围略有差异 → 用网页的「量化吸附 / 采样补偿 / 自动校准」调。

这些都不是「能不能跑」的死穴，但确实可能要针对具体机型调参。**这就是为什么我在开头写了那么大的警告，也欢迎懂 Swift / 熟悉私有框架的朋友一起来修。**

## 已知问题 / TODO（欢迎一起来完善）

这个工具离「好用」还差得远，下面这些都很需要人帮忙，也欢迎直接改：

- [ ] 采集器对**非 MacBook 原厂触控板**的兼容性没验证；
- [ ] 私有框架在**未来 macOS** 上如果符号变动，采集器需要跟进；
- [ ] 手势分类参数（死区 / 速度阈值）目前是拍脑袋定的，缺少按机型自动标定；
- [ ] 没有可视化地编辑判定线事件（speed / move / rotate），目前导出的流速等是固定默认；
- [ ] 录制时**没有**做触控板锁定（之前试过一版会干扰手势识别，已移除），误触目前靠手动避免；
- [ ] 导出目前只覆盖单个难度，多难度 / 多谱面工程管理待做；
- [ ] 没有跨平台方案（Windows / Linux 触控板协议不同）。

**如果你修好了上面任何一条，或加了新功能，请直接提 Pull Request。** 哪怕只是把某台机型的踩坑写进 Issues，对其他用户也是功德一件。
